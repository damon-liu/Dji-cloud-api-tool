Key → 中文 映射方案

PRD 要求：「每个topic的JSON数据都不一样，需要维护每个topic原始JSON中key对应的中文」
先实现 osd topic，但要为后续扩展留下空间

A

方案 A：外部 JSON 配置文件

创建一个独立的 topic_mappings.json 文件，按 topic 模式组织映射。
用户可直接编辑该文件添加新 topic 的映射，无需改代码。

B

方案 B：硬编码 + DJI 网页抓取

在 C++ 中硬编码 osd topic 的映射表。
后续可通过解析 DJI 官网 HTML 自动生成映射。

C

方案 C：合并到 config.json

在现有 config.json 中新增 mappings 段，与 MQTT 配置和设备列表放在一起。
不需要额外文件，但 config.json 会越来越臃肿。

方案 A 文件结构预览（推荐）

独立配置文件，清晰、可扩展、用户可直接编辑

topic_mappings.json — 按 topic 模式组织
{
  "topics": {
    "thing/product/{sn}/osd": {
      "description": "机场/无人机 OSD 遥测数据",
      "mappings": {
        "job_number":             { "zh": "累计作业次数", "unit": "次" },
        "electric_supply_voltage": { "zh": "供电电压",     "unit": "V" },
        "working_voltage":        { "zh": "工作电压",     "unit": "V" },
        "wind_speed":             { "zh": "风速",         "unit": "m/s" },
        "environment_temperature": { "zh": "环境温度",     "unit": "℃" },
        // 嵌套 key 用 "." 分隔
        "battery.capacity_percent":  { "zh": "电池电量", "unit": "%" },
        "battery.batteries[0].voltage": { "zh": "左电池电压", "unit": "mV" },
        "position_state.gps_number":  { "zh": "GPS 搜星数", "unit": "" }
      }
    },
    "thing/product/{sn}/state": {
      "description": "设备状态变化数据 (v1.1)",
      "mappings": { }
    }
  }
}

三种方案对比

方案 A 优点

  • 用户可自行编辑，无需改代码
  • 新增 topic 只需加一段 JSON
  • 文件独立，职责清晰
  • 支持嵌套 key (用 . 分隔)
  • 可附带 unit（单位）信息

方案 A 缺点

  • 多一个配置文件要管理
  • 首次需要写完整的映射表
  • 文件缺失时需要降级处理

方案 B 优点

  • 无需外部文件，部署简单
  • 编译期检查，类型安全
  • 零配置，开箱即用

方案 B 缺点

  • 新增映射需重新编译
  • 无法应对 DJI 新增字段
  • C++ 中维护大量字符串
